-------------------------------------------
WHAT THE PROJECT IS
-------------------------------------------
Rendevoo is a location-based meetup platform where users can discover,
create, and communicate in real-time meetups tied to real-world places.

It is NOT a CRUD app. The interesting parts are:
- Geospatial proximity search using Haversine formula in SQL
- Real-time WebSocket chat room per meetup
- JWT authentication
- Automated meetup expiry via @Scheduled background job

-------------------------------------------
TECH STACK
-------------------------------------------
Backend      : Spring Boot (Java)
Frontend     : not the focus right now
Database     : PostgreSQL with JPA/Hibernate
Auth         : JWT
Real-time    : WebSocket with STOMP
Maps         : Google Maps API
Places       : Google Places API
Deployment   : Railway (backend), Vercel (frontend), Supabase (PostgreSQL)

KEY TECHNICAL DECISIONS (for interview talking points)
-------------------------------------------
- Haversine over PostGIS: right tool for the scale, fully explainable
- Railway over Render: Render spins down after 15 mins, bad for demos
- JWT over sessions: stateless, fits REST architecture
- @Scheduled for expiry: background processing without external queue
- Pushed Haversine computation to DB layer, not in-memory filtering

-------------------------------------------
INTERVIEW ANSWERS (prepared)
-------------------------------------------
Q: Isn't this just a CRUD app?
A: The meetup management is CRUD, yes. But the interesting parts are
   the WebSocket chat room per meetup, geospatial proximity queries
   using the Haversine formula, and the background job that expires
   meetups and locks their chat rooms. Those aren't CRUD problems.

Q: Why Haversine and not PostGIS?
A: PostGIS is industry standard for serious geospatial applications
   but it's overkill for this scale. Haversine gives accurate
   great-circle distance with no extra dependencies, and I can explain
   every line of the query. Right tool for the scale.

Q: How does your WebSocket chat scale?
A: Honestly at this scale it doesn't need to. Each meetup has one
   chat room, connections are authenticated via JWT. For scale I'd
   look at a message broker like RabbitMQ or Redis pub/sub.

Q: Why Railway over Render?
A: Render's free tier spins down after 15 minutes of inactivity.
   Cold start takes 30-50 seconds — bad for demos and interviews.
   Railway's free credits keep the backend alive.
