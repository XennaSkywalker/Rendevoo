how to establish relationships between entities tables in springTo establish relationships between database tables in Spring, you use Spring Data JPA along with standard JPA annotations (like @ManyToOne, @OneToMany, @ManyToMany, and @OneToOne). These annotations map your Java classes (Entities) directly to the database tables and handle the Foreign Keys automatically.The standard approach for mapping entity relationships depends on the type of association you need to build.1. Many-to-One / One-to-ManyThis is the most common relationship (e.g., an Author can write many Books, but a Book has exactly one Author). The Foreign Key always lives on the Many side.java@Entity
public class Author {
    @Id
    @GeneratedValue(strategy = GenerationType.IDENTITY)
    private Long id;
    private String name;

    // One author has many books (mappedBy refers to the 'author' field in Book)
    @OneToMany(mappedBy = "author", cascade = CascadeType.ALL, fetch = FetchType.LAZY)
    private List<Book> books;
}

@Entity
public class Book {
    @Id
    @GeneratedValue(strategy = GenerationType.IDENTITY)
    private Long id;
    private String title;

    // Many books belong to one author (creates a foreign key column author_id in the DB)
    @ManyToOne
    @JoinColumn(name = "author_id", nullable = false)
    private Author author;
}
Use code with caution.2. One-to-OneUsed when exactly one record in a table is linked to exactly one record in another (e.g., an Employee has one ParkingSpace).java@Entity
public class Employee {
    @Id
    @GeneratedValue(strategy = GenerationType.IDENTITY)
    private Long id;
    private String name;

    @OneToOne(cascade = CascadeType.ALL)
    @JoinColumn(name = "parking_spot_id", referencedColumnName = "id")
    private ParkingSpot parkingSpot;

@Entity
public class ParkingSpot {
    @Id
    @GeneratedValue(strategy = GenerationType.IDENTITY)
    private Long id;
    private String spotNumber;
    
    // Optional: bidirectional (mappedBy matches the property name in Employee)
    @OneToOne(mappedBy = "parkingSpot")
    private Employee employee;
}
Use code with caution.3. Many-to-ManyUsed for complex relationships where multiple records in one table relate to multiple records in another (e.g., Students enrolling in many Courses). This requires an intermediate join table.java@Entity
public class Student {
    @Id
    @GeneratedValue(strategy = GenerationType.IDENTITY)
    private Long id;
    private String name;

    @ManyToMany
    @JoinTable(
        name = "student_course", // The intermediate join table
        joinColumns = @JoinColumn(name = "student_id"),
        inverseJoinColumns = @JoinColumn(name = "course_id")
    )
    private Set<Course> courses;
}

@Entity
public class Course {
    @Id
    @GeneratedValue(strategy = GenerationType.IDENTITY)
    private Long id;
    private String title;

    // Non-owning side uses mappedBy to reference the 'courses' collection in Student
    @ManyToMany(mappedBy = "courses")
    private Set<Student> students;
}

It tells the application not to load related data from the database until the exact moment you explicitly request it in your Java code.Think of it as "on-demand" loading.How it Works (The Visual Difference)Imagine you have a User who owns 500 Meetups.FetchType.EAGER (The Default for @ManyToOne):When you fetch a single Meetup from the database, Spring immediately runs a second hidden query (or a heavy SQL JOIN) to fetch the entire User profile as well, even if your code only needed to print the meetup's title.FetchType.LAZY (The Optimized Way):When you fetch a Meetup, Spring only loads the meetup data. The owner field is filled with a temporary, lightweight placeholder called a Proxy. The database is only queried for the User details if and when you explicitly call meetup.getOwner().getName().Why You Should Use LAZYSaves Memory and CPU: You avoid loading hundreds of child records into your server's RAM if you don't intend to use them.Prevents the "N+1 Query Problem": If you fetch a list of 10 meetups using EAGER, Spring might end up running 1 additional query per meetup to fetch their owners, resulting in 11 database calls instead of just 1. LAZY prevents this accidental spamming of your database.The Trade-off: LazyInitializationExceptionBecause the related data is loaded on demand, the database connection (Hibernate Session) must still be open when you request it.If you fetch a Meetup, close the transaction (e.g., exit the @Transactional service layer), and then try to call meetup.getOwner() inside a separate utility class or view layer, Spring will throw a LazyInitializationException.To prevent this error, you either:Keep the transaction open using @Transactional.Use a specialized JPQL query with JOIN FETCH when you know you need both entities at the same time.Would you like to see how to write a JOIN FETCH repository query to safely load lazy data when you actually need it?15 sitesLazy ReferencesIn Spring JPA, lazy loading is achieved by annotating a field or property with FetchType.     }

    @Autowired

    @Autowired

    @Transactional
    public void deleteUserAccount(long userId) {
        // 1. Verify the user exists first
        if (!userRepository.existsById(userId)) {
            throw new RuntimeException("User not found");
        }

        // 2. HTTP Call: Tell Meetup Service to change creatorId to 0 for this user
        restClient.put()
            .uri("/internal/meetups/clear-creator/" + userId)
            .retrieve()
            .toBodilessEntity(); // Executes the call, ignores response body

        // 3. Delete the user from the local database
        userRepository.deleteById(userId);
    }
